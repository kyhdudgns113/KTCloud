<summary><h2><strong>:bricks: Array</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 데이터를 연속된 형태로 저장하는 구조

    - 0부터 시작한다

- 자료구조의 n 번째 원소에 접근을 할때 유용함

- 보통은 메모리에 연속적으로 저장됨

    - 시작원소로부터 몇번째 원소인지로 접근함

    - 2차원 동적배열같은 경우는 메모리에 연속으로 저장이 안되기도함

</details>

<details>
<summary><strong>접근</strong></summary>

- O(1) 의 시간이 걸린다

- 원하는 순서의 원소를 인덱스로 검색이 가능하다

    - A[0], A[3] 이런식으로 접근이 가능하다

</details>

<details>
<summary><strong>탐색</strong></summary>

- O(n) 의 시간이 걸린다

- 정렬이 되어있지 않으면, 맨 앞 원소부터 하나씩 확인해야한다.

- 정렬이 되어있으면 Binary Search 로 O(log n) 으로 탐색이 가능하다

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- O(n) 의 시간이 걸린다(대부분)

    - C, Java 의 경우 배열을 처음 생성할때, 사용할 만큼만 배열을 메모리에 할당한다.

    - 배열에 원소를 삽입할때, 배열의 크기가 바뀌어야 하며, 메모리를 새로 할당해야 한다.

    - 기존 크기만큼 메모리를 할당하고, 값을 복사해야 하므로 O(n) 이 걸린다.

- O(1) 이 걸리는 경우도 있다

    - Node.js, Python 은 원소를 뒤에 삽입할때 O(1) 이 걸린다.

    - 이들은 배열을 선언할때 메모리를 넉넉하게 할당한다.

    - 배열의 뒤에 원소를 삽입할때, 할당한 공간이 남아있으면 그곳에 값을 넣기만 하면 된다.

        - 여기서 O(1) 이 소모된다.

    - 배열의 크기를 벗어날땐 메모리를 새로 할당해야 하므로 이 경우는 O(n) 이다.

        - 보통은 2배로 늘린다

        - 데이터 n 개당 O(n) 이 한 번 발생하므로 전체 n 을 기준으로는 O(1) 이다.

</details>

<details>
<summary><strong>참고</strong></summary>

- Python 은 배열을 List 라고 부른다.

    - <s>C 나 Java 를 하다가 Python 하면 제일 거슬린다</s>

</details>

</details>

<summary><h2><strong>:link: Linked List</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 각 원소가 값과 다음 원소의 위치를 가진다.

- 메모리에 붙어 있지 않아도 된다.

- 맨 앞부터 화살표를 따라간다.

    - 배열처럼 번호로 칸을 바로 열지 못한다.

</details>

<details>
<summary><strong>접근</strong></summary>

- O(n) 의 시간이 걸린다.

- n 번째를 보려면 맨 앞에서 n 번 이동한다.

</details>

<details>
<summary><strong>탐색</strong></summary>

- O(n) 의 시간이 걸린다.

- 맨 앞부터 값을 하나씩 비교한다.

- 정렬되어 있어도 중간 칸으로 건너뛰지 못한다.

    - 배열의 Binary Search 처럼 O(log n) 이 되지 않는다.

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- 넣을 위치를 알고 있으면 O(1) 의 시간이 걸린다.

    - 그 원소의 다음 위치만 바꾸면 된다.

    - 뒤 원소를 한 칸씩 밀지 않는다.

- 맨 앞에 넣는 것도 O(1) 이다.

    - 새 원소가 기존의 맨 앞을 가리키게 하면 된다.

- 위치를 맨 앞에서부터 찾아야 하면 찾는 데 O(n) 이 걸린다.

    - 표의 O(1) 은 위치를 알고 있을 때이다.

</details>

<details>
<summary><strong>참고</strong></summary>

- 다음만 가면 단일 연결 리스트, 앞뒤로 가면 이중 연결 리스트이다.

- Java 는 LinkedList, C 는 노드를 직접 만든다.

- Python 의 list 는 배열이다.

</details>

</details>

<details>
<summary><h2><strong>:key: Hash Map</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 키와 값을 저장한다.

- 키를 계산해서 배열의 칸 번호를 만든다.

    - 이 계산을 해시라고 부른다.

- 그 칸에 값을 둔다.

- 서로 다른 키가 같은 칸이 될 수 있다.

    - 그 칸에 연결 리스트로 이어 붙이는 방식이 흔하다.

</details>

<details>
<summary><strong>접근</strong></summary>

- O(1) 의 시간이 걸린다.

- 키만 있으면 칸 번호를 바로 계산한다.

- 한 칸에 키가 몰리면 그 칸을 하나씩 확인해서 O(n) 이 된다.

    - 표의 O(1) 은 칸에 고르게 들어갈 때이다.

</details>

<details>
<summary><strong>탐색</strong></summary>

- 키로 찾으면 O(1) 의 시간이 걸린다.

- 값만 알고 키를 모르면 모든 칸을 봐야 해서 O(n) 이다.

    - 표의 O(1) 은 키로 찾는 경우이다.

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- 키로 넣거나 빼면 O(1) 의 시간이 걸린다.

- 한 칸에 키가 몰리면 그 칸에서 키를 찾느라 O(n) 이 된다.

- 같은 키를 다시 넣으면 새 칸이 생기지 않고 값이 바뀐다.

</details>

<details>
<summary><strong>참고</strong></summary>

- Python 은 dict, Java 는 HashMap, JavaScript 는 Map 이다.

- 배열처럼 넣은 순서를 번호로 다루지 않는다.

</details>

</details>

<summary><h2><strong>:deciduous_tree: Tree</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 부모 아래에 자식을 두는 구조이다.

- 맨 위가 루트이고, 아래로 자식을 따라간다.

- 자식의 개수는 정해져 있지 않다.

- 배열처럼 번호로 칸을 열지 않는다.

</details>

<details>
<summary><strong>접근</strong></summary>

- 표기는 - 이다.

- 몇 번째인지 정하는 규칙이 없다.

- 보려면 루트에서 자식을 따라간다.

</details>

<details>
<summary><strong>탐색</strong></summary>

- 표기는 - 이다.

- 값이 어느 자식 쪽에 있는지가 정해져 있지 않다.

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- 표기는 - 이다.

- 자식을 어느 부모 아래에 둘지 정해져 있지 않다.

- 부모를 알고 있으면 그 아래에 자식을 붙이거나 뗄 수 있다.

</details>

<details>
<summary><strong>참고</strong></summary>

- 자식이 최대 두 개이면 이진 트리이다.

- 폴더 구조처럼 위아래 계층을 나타낼 때 쓴다.

</details>

</details>

<summary><h2><strong>:spider_web: Graph</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 정점과 간선으로 이루어진다.

- 정점은 값이고, 간선은 정점과 정점의 연결이다.

- 트리는 부모를 하나만 두는 그래프이다.

- 정점마다 연결된 정점 목록을 둔다.

    - 이 목록을 인접 리스트라고 부른다.

</details>

<details>
<summary><strong>접근</strong></summary>

- O(1) 의 시간이 걸린다.

- 정점 번호로 그 정점의 간선 목록을 연다.

</details>

<details>
<summary><strong>탐색</strong></summary>

- O(n) 의 시간이 걸린다.

- 한 정점에서 간선으로 이어진 정점으로 이동한다.

- 넓게 퍼져 나가면 Queue, 한 길을 끝까지 가면 Stack 을 쓴다.

- n 은 지나간 정점과 간선을 합친 개수이다.

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- O(1) 의 시간이 걸린다.

- 인접 리스트에 간선을 붙이거나, 목록의 맨 앞을 떼면 된다.

- 목록 안에서 특정 간선을 찾아 빼면 O(n) 이다.

    - 표의 O(1) 은 목록에 바로 붙이거나 맨 앞을 뗄 때이다.

</details>

<details>
<summary><strong>참고</strong></summary>

- 간선에 방향이 있으면 방향 그래프, 없으면 무방향 그래프이다.

- 간선에 비용이 있을 수 있다.

</details>

<summary><h2><strong>:trophy: Priority Queue</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 뺄 때 우선순위가 가장 높은 것이 나온다.

- 보통 Heap 으로 저장한다.

    - Heap 은 완전 이진 트리이고, 부모가 자식보다 우선순위가 높다.

    - 넣고 뺄 때 이 순서가 맞을 때까지 자리만 바꾼다.

</details>

<details>
<summary><strong>접근</strong></summary>

- O(1) 의 시간이 걸린다.

- 우선순위가 가장 높은 것, Heap 의 맨 위만 본다.

</details>

<details>
<summary><strong>탐색</strong></summary>

- O(n) 의 시간이 걸린다.

- 임의의 값은 정해진 방향이 없어 노드를 따라간다.

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- O(log n) 의 시간이 걸린다.

- Heap 에 넣은 뒤, 부모와 자식을 비교하며 올라간다.

- 맨 위를 뺀 뒤, 마지막 원소를 맨 위에 두고 아래로 내려간다.

- 배열에만 넣어 두면 뺄 때 전부를 봐야 해서 O(n) 이다.

    - O(log n) 은 Heap 기준이다.

</details>

<details>
<summary><strong>참고</strong></summary>

- Java 는 PriorityQueue, Python 은 heapq 이다.

</details>

<summary><h2><strong>:evergreen_tree: Binary Search Tree</strong></h2></summary>

<details>
<summary><strong>형태</strong></summary>

- 자식이 최대 두 개인 트리이다.

- 왼쪽은 자신보다 작고, 오른쪽은 자신보다 크다.

- 좌우 깊이가 맞으면 내려가는 횟수가 log n 이다.

    - 한쪽으로만 길어지면 연결 리스트와 같이 O(n) 이다.

</details>

<details>
<summary><strong>접근</strong></summary>

- O(log n) 의 시간이 걸린다.

- 루트에서 왼쪽 또는 오른쪽으로 내려간다.

</details>

<details>
<summary><strong>탐색</strong></summary>

- O(log n) 의 시간이 걸린다.

- 찾는 값이 노드보다 작으면 왼쪽, 크면 오른쪽으로 간다.

</details>

<details>
<summary><strong>삽입,삭제</strong></summary>

- O(log n) 의 시간이 걸린다.

- 삽입은 내려가다가 빈 자리에 넣는다.

- 삭제는 자식을 다시 잇는다.

    - 자식이 없으면 그 노드만 빼면 된다.

    - 자식이 있으면 왼쪽이나 오른쪽의 값을 올려 빈 자리를 채운다.

</details>

<details>
<summary><strong>참고</strong></summary>

- 이진트리 양옆의 균형을 맞추기위해 AVL Tree, Red-Black Tree 등이 있다.

    - 여기서 다루기엔 내용이 많이 길다

    - 구현이 정말 어렵다

- Java 의 TreeMap 이 이 계열이다.

- Python 에는 기본 이진 탐색 트리가 없다.

</details>
